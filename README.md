# how to run

- Run ```npm install -g nodemon``` to install the thing that runs the site
- Run ```npm install``` to install all of the packages for the site
- Run ```git submodule update --init --recursive``` to load in Space Company, Watermelon Game, and Getaway Shootout
- Run ```npm start``` to start the website. To access the website, go to the "ports" section of the terminal in the codespace, click "Forward a Port" and type in 3000. Once the port is forwarded, you can ctrl + click the website in the "Forwarded Address" section or press the website symbol that pops up by hovering over it.
    - There's a warning currently that shows up every time you run the website. This is probably normal. If something out of the ordinary does happen, feel free to contact me.

The goal is to keep styles consistent. This will make creating pages easier and faster. Redesigns in the future will also be simple. When making updates, please just keep everything consistent.


# How to make changes and whatnot

1. Read up on the structure of this repository and the best practices to use when editing it.
2. Make sure you are on YOUR OWN account (text me if you need me to give you access to this repository on a different account) 
3. Make a fork of this repository using the "fork" button in the top right (you only need to do this once)
4. Go to the newly made fork on your account and make changes. There are two ways to do this.
    - Either press the green button that says "code" in the top right, then press "codespaces", then create a new codespace (recommended)
    - Or press the pencil icon next to files that you have navigated to in GitHub (should probably only be done for quick edits)
5. Test your changes! If you are in a codespace, please use the "How to Run" directions above.
6. **MAKE SURE YOUR REPOSITORY IS UP TO DATE!!!** At this point, run ```git pull``` in your fork's codespace (if applicable).
7. Delete the "node_modules" folder. It's way too big to keep on the repository, and it can be generated by simply typing "npm install"
8. Commit your changes.
    -  If you are in a codespace, click the dot tree lookin icon thingy. Press "commit", then enter a commit message (basically an update name) in the new window that pops up above the hash tags. There should be a check mark in the top right that you can click on to save your changes. Afterwards, go back to the dot tree lookin thingy and sync your changes with your fork.
    - If you are using the pencil icon, just scroll down after editing, enter the commit message (update name) in the form below the code, and save the file to your fork.
9. Submit a pull request. Go to the main repository (not your fork) and select the "pull request" button at the top. Click the dropdowns provided and make sure you are merging your code into my repository correctly.

# Folders/Files and their Functions

- **games**
    - Stores all of the games (duh). These games are organized by web (html) and flash (swf) types. Please keep this organization consistent.
- **mc-client**
    - The future place for the Minecraft client. This folder is currently not in use.
- **src**
    - The main source of the website. This folder is organized as follows:
        - **assets**
            - Right now, this folder just contains stuff that would be useful for a redesign. This will get more organized in the future.
        - **css**
            - A place to put your different CSS files. **PLEASE DO NOT DELETE/OVERRIDE EXISTING CSS FILES. YOU MAY COPY/AND PASTE THEM IF WANT TO, THOUGH**.
        - **html**
            - A place to put your HTML files. The "core" subfolder contains stuff that is needed for constructing a webpage. You probably won't need to mess with it unless you are switching CSS files (method for doing this below). As a general rule, try not to mess with files that start with an underscore. They are probably vital to the structure/function of the webpage.
        - **md**
            - A place to store simple documents like the one you are reading right now. I'd recommend learning [Markdown's syntax](https://www.markdownguide.org/basic-syntax/) before creating or editing one of these documents.
- **.gitmodules**
    - A weird file that stores the modules that this repository uses. Please don't mess with this file.
- **gamelist.json**
    - A list that makes sure people aren't accessing flash games that aren't in the list. If you add a flash game (method below), make sure its name is added to this list.
- **games.js**
    - A file that routes the website connections for ALL games on the website. This reduces the clutter for the main file, index.js.
- **index.js**
    - The main file that routes all website connections. Please do not edit this file unless you know what you are doing by following the guides below.
- **package-lock.json**
    - Another weird file that keeps track of the packages used in this repository. Please don't edit this file.4
- **package.json**
    - A somewhat weird file that contains some attributes of this repository. You probably won't have to edit this.
- **README.md**
    - The file you are reading right now!

# Tutorials / Guides

If you don't know how to do something, please try to find it in one of these guides before ruining something or contacting me directly for help.

## How to Add a Game
- **HTML5/Web Game**
    1. Copy the game's files into ```games/web``` in its own, appropriately named folder.
    2. Use this template to add a new game to the ```games.js``` file, preferably at the bottom of the file. Replace (Game Folder Name) with your game's folder name (duh)
        ```js
        app.use('/games/(Game Folder Name)', express.static('./games/web/(Game Folder Name)'))

        app.route('/games/(Game Folder Name)').get((req, res) => {
            var page = fs.readFileSync('./games/web/(Game Folder Name)/index.html')
            res.send(page);
        });
        ```
    3. Add a link using [Markdown syntax](https://www.markdownguide.org/basic-syntax/) to the ```src/md/games.md``` file. To the page you just created. Use the other links as a guide and make sure you put the game into the correct section of links.
- **Flash Game**
    1. Add the .swf file of a game to the ```games/flash``` folder. Make sure it has a legible name.
    2. Add the name of the file **without the .swf part** to the ```gamelist.json``` file. Use the other games as a guide to correctly add in your game name. **Make sure your game name has a comma after it. If it is the last one in the gamelist, put a comma after the game before it instead.**
    3. Add a link using [Markdown syntax](https://www.markdownguide.org/basic-syntax/) to the ```src/md/games.md``` file. To the page you just created. Use the other links as a guide and make sure you put the game into the correct section of links.
## How to Switch / Edit a CSS file

1. Create a new CSS file in the ```src/assets``` folder. I *strongly* encourage you to copy from the pre-existing ```basic.css``` file.
2. Edit your newly created file and give it a cool name 😎
3. To switch the website to utilize your new CSS file, go to the file ```src/html/core/_header.html```. In the part where it says ```href="basic.css"```, replace your file with the ```basic.css``` file like this:
```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <link rel="stylesheet" href="/mycoolstyle.css">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>placeholder</title>
</head>
<body>
```

# How to create a new (non-game) page
Simply use this template and paste it into a new spot **before the 404 error handler** in ```index.js```. Replace the green highlighted words (and the /* and */ part) with what is called for inside of them. Please do not delete anything outside of these green comments.
```js
app.route(/* Web page path. Example (including single quotes): '/mypage' */).get((req, res) => {
    var page = getPage(/* Webpage title. Example (including quotes): "My Cool Page!"*/, [/* How the website is constructed. This is a list of paths to webpage elements, wrapped in quotes and separated by commas. The core files are already included. Example: "/html/_topbar.html", "/md/mypage.md", "/html/_credits.html" */]);
    res.send(page);
})
```
This example would create a page at the address https://sciencelabz.education:3000/mypage with a title in the tab at the top of "My Cool Page!", a standard top bar, a custom markdown document in the middle, and standard credits at the bottom.
